### New Understanding
- `title` should describe the current app status, for example `Practice Running`.
- `buttonTitle` should describe the action the button will do, for example `Pause`.
- `Button { ... }` contains an action closure that runs only when the button is tapped.
- `switch practiceStatus` reads the current state and chooses the matching case.
- Changing an `@State` value causes SwiftUI to render `body` again.
- Views that read `practiceStatus.title`, `practiceStatus.buttonTitle`, or conditional state update when `practiceStatus` changes.
- `if` inside SwiftUI `body` controls whether a view is included in the UI.
- The timer publisher can keep sending ticks, but `elapsedSeconds` only increases when `practiceStatus == .practiceStarted`.
- `enum` is good for a main state where only one case should be active at a time.
- If an app needs multiple conditions at once, it can combine an enum with extra `@State` values or a struct.

  - `.practice` menampilkan `PracticeView`

### Catatan Konsep - RootView

`Challenge5App.swift` adalah entry point app. Tugasnya membuat scene pertama lewat `WindowGroup`.

`RootView.swift` dipakai sebagai pengatur flow/screen utama app. RootView yang menentukan app sedang menampilkan Home, Practice, Recap, atau screen lain nanti.

`HomeView.swift` fokus ke tampilan dan behavior halaman Home, bukan mengatur seluruh perpindahan screen app.

Mental model:

```text
Challenge5App = pintu masuk app
RootView = penjaga flow/screen app / ruang tengah app
HomeView = isi screen Home
```

Karena itu app memakai:

```swift
WindowGroup {
    RootView()
}
```

bukan langsung:

```swift
WindowGroup {
    HomeView()
}
```

Langsung memakai `HomeView()` itu valid kalau app cuma punya satu screen. Tapi `RootView` mulai berguna saat app butuh flow multi-screen seperti:

```text
Home → Practice → Recap → Home
```

### Catatan Konsep - `switch activeScreen`

`activeScreen` menyimpan screen yang sedang aktif.

```swift
@State var activeScreen: ActiveScreen = .home
```

`switch activeScreen` mengecek nilai `activeScreen` saat ini.

```swift
switch activeScreen {
case .home:
    HomeView(...)
case .practice:
    PracticeView()
}
```

Artinya:
- kalau `activeScreen == .home`, body menghasilkan `HomeView`
- kalau `activeScreen == .practice`, body menghasilkan `PracticeView`

Jadi kalau ingin pindah screen, yang perlu diubah adalah value state-nya:

```swift
activeScreen = .practice
```

Setelah `@State` berubah, SwiftUI menghitung ulang `body`, lalu `switch activeScreen` memilih view baru.

### Catatan Konsep - Closure Callback

`onStartPractice` memakai tipe:

```swift
() -> Void
```

Artinya:
- `()` = closure ini tidak butuh input/data dari pemanggil.
- `Void` = closure ini tidak mengembalikan output.

Ini cocok karena `HomeView` hanya perlu mengirim event:

```text
"Start Practice ditekan."
```

`onStartPractice` bukan untuk menghitung data. Ia adalah sinyal kejadian/callback.

`HomeView` tidak perlu tahu cara pindah screen. HomeView cukup memberi kabar:

```text
"Start kepencet nih."
```

Lalu `RootView` yang memutuskan:

```text
"Screen aktif sekarang Practice."
```

### Kenapa `HomeView` Harus Diisi `onStartPractice`

`HomeView` punya property:

```swift
let onStartPractice: () -> Void
```

Karena property ini tidak punya default value, setiap tempat yang membuat `HomeView` wajib mengisinya.

Di flow app asli, `RootView` memberikan aksi nyata:

```swift
HomeView(
    onStartPractice: {
        activeScreen = .practice
    }
)
```

Di preview, cukup pakai closure kosong:

```swift
HomeView(onStartPractice: {})
```

`{}` artinya: kalau closure ini dipanggil, tidak melakukan apa-apa.

Perbedaan penting:
- di Preview, `{}` aman karena preview hanya perlu menampilkan UI, tidak perlu benar-benar pindah screen.
- di app asli, kalau `RootView` memakai `onStartPractice: {}`, tombol Start tidak akan memindahkan screen karena tidak ada state yang berubah.
- di `RootView`, closure harus berisi aksi nyata seperti `activeScreen = .practice`.

### Closure Disimpan Dulu, Baru Dieksekusi

Saat `RootView` menulis:

```swift
HomeView(
    onStartPractice: {
        activeScreen = .practice
    }
)
```

closure itu belum langsung jalan. Closure hanya dikirim dan disimpan di property `onStartPractice` milik `HomeView`.

Closure baru jalan saat `HomeView` memanggil:

```swift
onStartPractice()
```

Perbedaan penting:

```text
onStartPractice: { activeScreen = .practice }
= menyimpan aksi untuk nanti

onStartPractice()
= menjalankan aksi yang sudah disimpan
```

### Kenapa Isi Closure Bukan `PracticeView()`

Closure tidak seharusnya langsung berisi:

```swift
PracticeView()
```

Karena itu hanya membuat value `PracticeView`, tapi tidak mengganti UI yang sedang tampil.

Di SwiftUI, UI yang tampil berasal dari hasil `body`.

Dalam kasus ini, hasil `body` `RootView` ditentukan oleh:

```swift
switch activeScreen
```

Jadi pola yang benar adalah:

```text
event terjadi → state berubah → body render ulang → switch memilih View baru
```

Karena itu isi closure adalah perubahan state:

```swift
activeScreen = .practice
```

Lalu setelah `body` dihitung ulang, `RootView` masuk ke:

```swift
case .practice:
    PracticeView()
```

### Catatan Konsep - `switch practiceStatus`

`switch practiceStatus` mengecek status sebelum tombol ditekan.

Saat user pertama kali menekan Start Practice, status awalnya adalah:

```swift
.ready
```

Maka kode yang jalan adalah:

```swift
case .ready:
    practiceStatus = .practiceStarted
    onStartPractice()
```

`onStartPractice()` diletakkan di `case .ready` karena event-nya adalah:

```text
dari kondisi ready → mulai practice
```

Bukan di `case .practiceStarted`, karena `case .practiceStarted` artinya sebelum tombol ditekan, statusnya sudah running. Dalam flow sebelumnya, case itu dipakai untuk pause:

```text
practiceStarted → paused
```

### Alur Eksekusi End-to-End

Alur runtime-nya:

```text
App mulai
→ Challenge5App membuat WindowGroup
→ WindowGroup menampilkan RootView
→ RootView membuat @State activeScreen = .home
→ body RootView dijalankan
→ switch activeScreen mengecek value saat ini
→ activeScreen bernilai .home
→ HomeView tampil
→ RootView mengirim closure onStartPractice ke HomeView
→ closure disimpan, belum dieksekusi
→ user tap Start Practice
→ Button action di HomeView jalan
→ switch practiceStatus mengecek status sebelum tap
→ case .ready jalan
→ practiceStatus berubah menjadi .practiceStarted
→ HomeView memanggil onStartPractice()
→ closure dari RootView dieksekusi
→ activeScreen berubah menjadi .practice
→ SwiftUI melihat @State berubah
→ body RootView dihitung ulang
→ switch activeScreen sekarang masuk case .practice
→ PracticeView tampil
```

### Rule Praktis

Kalau ada closure action seperti:

```swift
let onStartPractice: () -> Void
```

Tanya:

```text
Saat event ini terjadi, parent perlu mengubah apa?
```

Untuk Milestone 2, jawabannya:

```swift
activeScreen = .practice
```

Karena yang menentukan screen tampil adalah state `activeScreen`.
