Yang gua pahami:

`Button ditekan → state berubah → body dihitung ulang → Text tampil dengan nilai baru`

## Update - Enum untuk Practice Status

Behavior yang sedang dibangun:
- Home screen punya status practice.
- Awalnya status tampil `Ready`.
- Saat button ditekan, status berubah jadi `Practice Started`.

Masalah dari versi String:
- Sebelumnya state disimpan sebagai `String`.
- `String` terlalu bebas, jadi typo seperti `Practise Started` tetap bisa terjadi.
- Swift tidak tahu apakah typo itu salah secara makna, selama bentuknya tetap String.

Perubahan yang gua buat:
- Gua bikin enum `PracticeStatus`.
- Case-nya:
  - `.ready`
  - `.practiceStarted`
- State di `HomeView` berubah jadi:
  - `@State var practiceStatus: PracticeStatus = .ready`

Yang gua pahami:
- Enum cocok kalau pilihan statusnya terbatas.
- `PracticeStatus` jadi tipe resmi untuk status practice.
- Karena tipe `practiceStatus` sudah jelas `PracticeStatus`, action button bisa menulis `.practiceStarted` tanpa menulis `PracticeStatus.practiceStarted`.
- Ini disebut dot shorthand / type inference dari konteks.

Tentang `title`:
- `title` di enum berfungsi sebagai translator dari status internal ke teks yang tampil di UI.
- Contoh:
  - `.ready` → `"Ready"`
  - `.practiceStarted` → `"Practice Started"`
- Jadi `Text(practiceStatus.title)` menampilkan teks berdasarkan status saat ini.

Runtime flow:
`Button ditekan → practiceStatus berubah ke .practiceStarted → SwiftUI menghitung ulang body → Text membaca practiceStatus.title → UI menampilkan "Practice Started"`

Next question:
- Kalau nanti status practice bertambah, misalnya paused / finished, bagaimana enum membantu menjaga UI tetap aman dan jelas?

## Update - Behavior Eksekusi: Button Action vs Computed Property

Hal yang bikin gua lebih paham:
- Yang berubah bukan `title` atau `buttonTitle`.
- Yang berubah adalah `practiceStatus`.
- `title` dan `buttonTitle` cuma menghasilkan teks berdasarkan nilai `practiceStatus` terbaru.

Urutan eksekusi dari kode:

1. State awal dibuat:
   - `@State var practiceStatus: PracticeStatus = .ready`
   - Artinya saat `HomeView` pertama muncul, `practiceStatus` bernilai `.ready`.

2. UI membaca status title:
   - Kode UI: `Text(practiceStatus.title)`
   - Karena `practiceStatus == .ready`, computed property `title` masuk ke:
     - `case .ready: return "Ready"`
   - UI menampilkan `Ready`.

3. UI membaca button title:
   - Kode UI: `Text(practiceStatus.buttonTitle)`
   - Karena `practiceStatus == .ready`, computed property `buttonTitle` masuk ke:
     - `case .ready: return "Tap to Start"`
   - Button menampilkan `Tap to Start`.

4. Saat button diklik:
   - Yang dieksekusi adalah block action di `Button { ... }`.
   - Karena `practiceStatus == .ready`, switch action masuk ke:
     - `case .ready: practiceStatus = .practiceStarted`
   - State berubah menjadi `.practiceStarted`.

5. Karena `@State` berubah:
   - SwiftUI menghitung ulang `body`.
   - `Text(practiceStatus.title)` dibaca ulang.
   - Sekarang `title` masuk ke:
     - `case .practiceStarted: return "Practice Started"`
   - UI menampilkan `Practice Started`.

6. Button label juga dibaca ulang:
   - `Text(practiceStatus.buttonTitle)`
   - Sekarang `buttonTitle` masuk ke:
     - `case .practiceStarted: return "Pause"`
   - Button berubah menjadi `Pause`.

Ringkasan mental model:
`Button action mengubah practiceStatus → @State trigger render ulang → title/buttonTitle dihitung ulang → UI berubah`

Catatan penting:
- Computed property seperti `title` dan `buttonTitle` dipakai untuk menghasilkan nilai.
- Button action dipakai untuk melakukan efek/perubahan.
- `return` cocok di computed property karena ia harus mengembalikan nilai.
- Assignment seperti `practiceStatus = .practiceStarted` cocok di Button action karena ia mengubah state.

## Update - Conditional UI dan Transition Flow

Behavior yang sudah verified di Preview:
- Saat status `.ready`:
  - Status text: `Ready`
  - Main button: `Tap to Start`
  - Stop button belum muncul.
- Tap `Tap to Start`:
  - `practiceStatus` berubah ke `.practiceStarted`
  - Status text menjadi `Practice Started`
  - Main button menjadi `Pause`
  - Stop button muncul.
- Tap `Pause`:
  - `practiceStatus` berubah ke `.paused`
  - Status text menjadi `Paused`
  - Main button menjadi `Resume`
  - Stop button tetap muncul.
- Tap `Resume`:
  - `practiceStatus` berubah balik ke `.practiceStarted`
  - Main button menjadi `Pause`
  - Stop button tetap muncul.
- Tap `Stop`:
  - `practiceStatus` berubah ke `.finished`
  - Status text menjadi `Finished`
  - Main button menjadi `Done`
  - Stop button hilang.
- Tap `Done`:
  - `practiceStatus` berubah balik ke `.ready`.

Yang gua pahami:
- State disimpan di variable `practiceStatus`.
- Tipe state-nya adalah enum `PracticeStatus`.
- Nilai awalnya `.ready`.
- `@State` membuat SwiftUI memantau perubahan `practiceStatus`.
- Saat `practiceStatus` berubah, SwiftUI menghitung ulang `body`.

Tentang `if` di body:
- `if` di dalam `body` menentukan apakah sebuah view dibuat/ditampilkan.
- Stop button hanya muncul kalau:
  - `practiceStatus == .practiceStarted`
  - atau `practiceStatus == .paused`
- Kalau status `.ready` atau `.finished`, kondisi `if` false, jadi Stop button tidak muncul.

Mental model:
`practiceStatus berubah → body dihitung ulang → if dicek ulang → UI menampilkan view yang sesuai state`

Konsep yang dipakai:
- `@State`
- `enum`
- computed property
- `switch`
- `Button` action
- `if` conditional UI

```text

```

- original Tiempo source perlu dibaca sebelum/selama rebuild,
- syntax yang sudah dipakai di original Home perlu dibahas beserta pertimbangannya,

- fitur lama boleh disesuaikan lagi saat milestone berikutnya membutuhkan refactor.
