## Learning Notes

### SwiftUI syntax starter patterns

Saat Fian stuck di “sintaks pertama yang harus diketik”, gunakan pola awal yang jelas:

- Kalau mau nampilin teks/data ke layar, biasanya mulai dari `Text(...)`.
- Kalau mau bikin sesuatu yang bisa ditap, bentuk awalnya adalah `Button`.
- Kalau value bisa berubah dan UI harus ikut berubah, gunakan `@State var ...`.

### Stored vs computed property

Patokan singkat:

```text
= nilai awal          → stored property, menyimpan value
{ return ... }        → computed read-only, menghitung/mengembalikan value
{ get ... set ... }   → computed property yang bisa dibaca dan di-assign
```

Catatan dari kode Home:
- `@State var elapsedSeconds: Int = 0` menyimpan angka detik.
- `var title: String { ... }` hanya menerjemahkan status menjadi teks.
- `title` / `buttonTitle` boleh dibaca di UI, tetapi tidak bisa di-assign kalau tidak punya `set`.

## Milestone 1B-3 - Automatic Timer Tick

Focus:
- Continue Tiempo iOS automatic timer behavior.
- Scope hanya timer tick, belum masuk PracticeResult, Recap, atau refactor architecture.

Hands-on:
- Menambahkan `import Combine`.
- Menambahkan timer publisher di `HomeView`:
  - `Timer.publish(every: 1, on: .main, in: .common).autoconnect()`
- Menambahkan `.onReceive(timer)` di root `ZStack` untuk menangkap tick.
- Build verified after adding timer publisher and `.onReceive`.

My understanding:
- Kita butuh Combine karena timer ini bekerja sebagai Publisher: Timer mengirim event/tick tiap 1 detik, lalu `.onReceive` menangkap event itu dan menjalankan kode.
- `Timer.publish(...)` membuat pengirim tick.
- `.autoconnect()` membuat publisher otomatis mulai saat ada yang mendengarkan.
- `.onReceive(timer)` adalah penerima tick.
- `_ in` berarti closure menerima value dari timer, tapi value itu diabaikan.
- Value timer biasanya berupa `Date`; walaupun value tidak dipakai, event tick tetap membuat closure jalan.
- `@State` di luar `body` adalah tempat data disimpan.
- `Text` di dalam `body` adalah tempat data dibaca.
- `.onReceive` di root view adalah tempat event timer ditangkap karena timer mengubah state milik `HomeView`.

High-level timer flow:
```text
Timer.publish(every: 1...) bikin jadwal tick tiap 1 detik.
.autoconnect() mulai aktif saat .onReceive mendengar.
Timer didaftarkan ke main RunLoop.
RunLoop menunggu event.
Saat 1 detik lewat, Timer fire.
Publisher mengirim value Date ke .onReceive.
Closure .onReceive dijalankan.
Karena kita pakai `_`, Date dibuang.
elapsedSeconds += 1 tetap jalan.
```
